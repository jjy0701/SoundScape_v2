# (09) 강의실 실측과 3D 시뮬레이션 상대 레벨 비교

분석일: 2026-09-19. 이 결과는 분석 환경의 Python 3.12 / pyroomacoustics 0.10.1에서 계산했습니다. 사용자의 Windows PC에서 실행한 08번 설정을 그대로 재사용한 후속 계산이며, 이번 09번을 사용자 PC에서도 실행했다고 기록하지 않습니다.

## 1. 이번에 확인한 조건

사용자는 “위치만 옮긴거야 다 유지했어”라고 확인했습니다. 앞선 질문에 따라 두 스피커, 같은 재생 원본과 음량, 앱 설정, 휴대폰 방향, 가로 중앙과 높이를 유지한 것으로 기록합니다. 근거는 사용자 보고이며, 장비 로그나 별도 측정으로 검증한 것은 아닙니다.

| 항목 | 이번 비교의 입력 |
|---|---|
| 방 가로·세로·높이 | 7.50 × 10.25 × 2.63 m, 기존 잠정 치수 |
| 왼쪽 스피커 | (0.52, 3.10, 2.50) m |
| 오른쪽 스피커 | (6.55, 3.10, 2.50) m |
| P01 | (3.75, 2.50, 0.706) m |
| P02 | (3.75, 5.00, 0.706) m |
| P03 | (3.75, 7.50, 0.706) m |

좌표의 측정 오차나 스피커의 정확한 음향 중심은 아직 확인하지 않았습니다. 설정을 유지했다는 사실이 AGC 해제나 실제 녹음 gain의 시간 불변성을 증명하지는 않습니다. AGC 상태는 미확인으로 유지합니다.

## 2. 결과

실측과 합성 신호 모두 **250–4,000 Hz**를 같은 필터로 분석했습니다. 각각의 세 지점 레벨에서 **P02 값 하나만 빼서** 상대 레벨을 구했습니다.

| 지점 | 실측: P02 대비 (dB) | 모델: P02 대비 (dB) | 모델 − 실측 (dB) |
|---|---:|---:|---:|
| P01 | +2.3554 | +0.5409 | −1.8146 |
| P02 | 0.0000 | 0.0000 | 기준점이므로 평가 제외 |
| P03 | −2.1293 | −0.6254 | +1.5039 |

현재 가정의 모델은 앞쪽과 뒤쪽의 차이를 실측 녹음보다 작게 예측합니다. P01−P03 차이는 실측 약 4.485 dB, 모델 약 1.166 dB입니다.

비기준 지점 P01/P03 두 개의 상대 차이에 대한 MAE는 1.6592 dB, RMSE는 1.6665 dB입니다. 두 값은 P02라는 공통 기준을 공유합니다. 독립적인 두 실험의 통계나 강의실 전체 정확도가 아니며, 보정된 절대 SPL 오차 또는 기존 2D AI의 test RMSE 1.0627 dB와도 구분합니다. P02는 정의상 차이가 0이므로 오차 평균에 넣지 않았습니다.

## 3. 계산 방법

1. 기존 08번과 동일한 3D ShoeBox, 무지향성 음원·수음점, 벽/바닥/천장 흡음률 0.2를 사용했습니다. 좌우 같은 신호, 상대 출력 1:1, 같은 극성, 추가 지연 0은 계속 **가정값**입니다. 사용자가 설정을 유지했다는 확인으로 이 값들을 실측값으로 바꾸지 않았습니다.
2. 각 스피커의 RIR과 같은 시험 신호를 컨볼루션하고, 두 파형을 먼저 합산했습니다. 이는 [Pyroomacoustics 공식 시뮬레이션 방식](https://pyroomacoustics.readthedocs.io/en/pypi-release/pyroomacoustics.room.html)에 따른 것입니다. 사용한 설치 버전은 0.10.1입니다.
3. 실측은 이전 06번 코드에서 검출한 각 10초 구간의 중앙 8초를 사용했습니다. 합성 신호는 08번과 같은 6–14초, 21–29초, 36–44초를 사용했습니다. 시작·끝 과도 구간을 제외한 구간 레벨 비교이며, 표본별 파형 오차나 전파 지연을 측정한 것이 아닙니다.
4. 전체 파형에 동일한 `butter(4, [250, 4000], btype='bandpass', output='sos')`와 `sosfiltfilt`를 적용한 후 구간을 잘랐습니다. 전후 방향 필터링이므로 전달 특성도 함께 기록했습니다. A-weighting은 적용하지 않았습니다.
5. 세 구간 총 24초의 제곱 평균에서 레벨을 계산했습니다. 배경 소음을 빼거나 지점별 음량을 따로 정규화하지 않았습니다. 실측의 절대 숫자는 dBFS이며 모델의 절대 숫자는 미보정 모델 단위입니다. 두 절대값을 직접 빼지 않고 각 분포의 P02 대비 차이만 비교했습니다.

이전 녹음 검사 표는 별도 필터가 없는 전체 대역의 값이었습니다. 그때 P01−P03은 약 4.630 dB였고, 이번 공통 대역에서는 약 4.485 dB입니다. 분석 대역 차이에 따른 값이며 녹음 파일을 바꾸거나 결과를 맞춘 것이 아닙니다. 필터 없는 보조 비교도 JSON에 보존했으며 같은 방향의 차이를 보였습니다.

## 4. 검사한 내용

- 세 지점·두 스피커의 0차 직접음 도착 시간을 거리/음속과 비교했습니다. 라이브러리 분수 지연 필터의 40 samples를 제외한 차이는 모두 1 sample 이내였습니다.
- 개별 컨볼루션 합과 RIR 합의 컨볼루션, Pyroomacoustics 자체 `simulate()`를 대조했습니다. 모두 수치적으로 일치했습니다.
- P02의 필터 없는 16→32차 레벨 변화는 +0.1609639 dB로 기존 08번 결과를 재현했습니다.
- 250–4,000 Hz에서 P02를 기준으로 한 상대 분포의 16→32차 변화는 P01 약 −0.0187 dB, P03 약 +0.0688 dB였습니다. 이는 이번 상대 레벨 차이보다 작지만, 모든 위치·주파수·잔향에 대한 수렴 증명은 아닙니다.
- 원본 WAV의 SHA-256을 기존 분석 기록과 대조했습니다. 원본 편집, 소음 제거, 녹음 음량 변경은 수행하지 않았습니다.
- 저장한 NPZ의 수치 배열이 유한한 값인지 확인했습니다.

## 5. 연구적으로 어떻게 해석해야 하나요?

이번에는 실제 녹음과 모델을 같은 기준으로 비교하여 차이를 확인했습니다. 현재 모델이 검증 완료되었다고 결론내릴 단계는 아닙니다.

후보 원인으로는 실제 스피커 지향성과 장착 방향, 주파수별 흡음, 가구와 책상 반사, 스피커 좌우 응답 차이, 휴대폰 주파수 응답·자동 처리, 좌표 근사 등이 있습니다. 지금 세 점의 통합 레벨만으로 하나를 원인으로 특정할 수 없습니다.

다음 분석에서는 우선 현재 고정 모델의 주파수대별 차이를 살펴보고, 가능한 지향성·배치 기록을 보완합니다. 흡음률이나 출력 등을 맞추는 실험을 한다면 보정용 자료로 명시하고, 새 위치·새 배치 또는 독립 반복을 최종 평가용으로 확보합니다. 이 세 지점을 보고 조정한 모델을 다시 같은 세 지점으로 평가하여 독립 검증이라고 하지 않습니다.

| 파일 | 내용 |
|---|---|
| `compare_classroom(09_실측시뮬레이션비교).py` | 이번 상대 레벨 비교를 재현하는 실행 코드 |
| `support/` | 07/08 코드·설정 스냅샷, 녹음 분석 구간 및 사용자 확인 기록 |
| `results/metrics(01_실측비교수치).json` | 상세 수치·입력 해시·모든 가정·검사 결과 |

| `results/rirs(03_세지점원시RIR).npz` | 각 지점의 두 음원에 대한 32/16차 RIR 및 필터 계수 |

`support`의 07번 설정은 원래 기록의 스냅샷이어서 P01/P03이 `planned`로 남아 있습니다. 신규 녹음과 조건 확인은 `measurement_inputs(09_녹음구간과조건).json`에 기록했습니다. 09번은 이를 확인하고 기존 좌표를 사용합니다. 사용자의 현재 설정 파일을 과거 스냅샷으로 덮어쓰지 마세요.

NPZ에는 긴 전체 합성 파형을 중복 저장하지 않았습니다. 원본 시험 신호와 지점별 RIR로 재계산할 수 있습니다. 음향 가정을 조정하지 않은 이번 기준 실험은 별도로 보존합니다.

## 7. VS Code에서 재현하기

이미 계산한 수치와 그림을 확인하는 데 재실행은 필요하지 않습니다. 재현하려면 압축을 별도 폴더에 풀고, 프로젝트 `.venv`의 Python을 사용합니다. 녹음 세 파일은 한 폴더에 모으고 아래 경로를 실제 위치로 바꿉니다.

```powershell
& "C:\Users\space\OneDrive\바탕 화면\sound_scape\.venv\Scripts\python.exe" `
  ".\compare_classroom(09_실측시뮬레이션비교).py" `
  --reference "원본시험신호폴더\test_signal(06_예비녹음_50초).wav" `
  --recordings-dir "세녹음을모아둔폴더"
```

필요 녹음 파일명은 `앞쪽 2.5m.wav`, `테스트 녹음 2.wav`, `앞쪽벽 7.5m.wav`입니다. 입력 해시가 다르면 중단하므로 편집·변환한 파일을 대신 사용하지 않습니다. 의존성은 기존 환경의 NumPy, SciPy, Matplotlib, pyroomacoustics 0.10.1입니다. 원본 녹음과 시험 WAV는 이 압축에 중복 포함하지 않았습니다.

이번 코드는 기존 08번 P02 결과 재현 검사까지 포함한 고정 기준 비교입니다. 다른 방이나 설정을 평가하는 범용 코드로 사용할 때는 이 기준 검사의 적용 범위부터 수정해야 합니다.
